## 1. 研究领域

本周继续围绕 `FFGO` 视频定制模型的蒸馏可行性验证展开，重点从上一阶段的 `Wan2.1 T2V 1.3B` placeholder teacher 训练闭环，推进到 `FastGen` 原生 `Wan2.2 TI2V 5B / WanI2V / DMD2` 路线。

当前关注点包括：

1. 验证 `FastGen` 原生 `Wan2.2 TI2V 5B` 蒸馏框架是否能在当前服务器环境下稳定训练；
2. 明确公开 `FFGO (Wan2.2-I2V-A14B + LoRA)` 与当前 FastGen 原生 `Wan2.2 TI2V 5B` 路线之间的接口差异；
3. 在训练资源有限的情况下，先完成可复现的 `Wan2.2 I2V` 蒸馏基线，再决定如何接入真实 FFGO teacher。

## 2. 领域核心问题

当前核心问题仍然不是最终画质，而是 **FFGO 接入前的蒸馏 pipeline 是否具备可持续推进条件**。

具体来说，本周遇到的主要挑战是：

1. **公开 FFGO 与 FastGen 原生训练接口不直接等价。**
   FFGO 公开路线基于 `Wan2.2-I2V-A14B + LoRA adapter`，而服务器上可直接训练验证的是 `FastGen` 原生 `Wan2.2 TI2V 5B / WanI2V` 配置。

2. **Wan2.2 5B DMD2 的显存压力明显高于上一阶段 Wan2.1 1.3B 前置实验。**
   DMD2 同时包含 student、teacher、fake_score 和 discriminator，多模块 FSDP 后单卡峰值仍接近 30GB。

3. **官方原生配置不能在当前资源下无修改跑通。**
   官方 `config_dmd2_wan22_5b.py` 默认 `guidance_scale=5.0`，在当前 32GB GPU 上会在第一次真实 student update 时 OOM。

4. **GPU 资源不稳定影响实验连续性。**
   本周多次遇到 GPU 被其他任务占用或部分显存残留的问题，需要在每次启动前做更严格的 GPU precheck。

## 3. 技术方案

本周采用的策略是：保留 `FastGen` 原生 `Wan2.2 TI2V 5B` 的 DMD2 训练主干，只对当前硬件无法承受的部分做最小必要覆盖。

官方配置核对结果如下：

- 配置文件：`fastgen/configs/experiments/WanI2V/config_dmd2_wan22_5b.py`
- student：`Wan22_I2V_5B_Config`
- student sampling：`student_sample_steps = 2`
- sampling type：`student_sample_type = "ode"`
- time schedule：`t_list = [0.999, 0.833, 0.0]`
- DMD2 组件：
  - student/net：`Wan22_I2V_5B_Config`
  - teacher：默认由同一 net config 构建
  - fake_score：另一个 Wan I2V 5B 网络
  - discriminator：`Discriminator_Wan22_5B_Config`
- 优化设置：
  - `net_optimizer.lr = 1e-5`
  - `fake_score_optimizer.lr = 1e-5`
  - `discriminator_optimizer.lr = 1e-5`
  - `gan_loss_weight_gen = 0.03`
  - `student_update_freq = 5`
- 官方训练目标：
  - `max_iter = 5000`
  - `logging_iter = 100`
  - `save_ckpt_iter = 500`

在当前服务器上的可运行覆盖为：

- `trainer.ddp=False`
- `trainer.fsdp=True`
- `trainer.fsdp_cpu_offload=True`
- `trainer.batch_size_global=2`
- `dataloader_train.batch_size=1`
- `model.guidance_scale=null`
- `FASTGEN_DISABLE_MEDIA_LOGGING=true`

这里 `model.guidance_scale=null` 是本周最关键的资源适配项。它不是最终理论最优配置，而是当前 2 张 32GB GPU 上可以跨过 DMD2 student update 的可运行路线。

## 5. 结论与发现

本周的主要结论如下：

1. **`FastGen` 原生 `Wan2.2 TI2V 5B / DMD2` 路线可以训练，但需要资源适配。**
   在当前服务器上，完全原生 `guidance_scale=5.0` 不能稳定跨过 student update；但 `guidance_scale=null` 配合 FSDP CPU offload 可以完成 1000iter 并 resume 到 5000iter。

2. **当前进展不是最终 FFGO teacher 蒸馏效果，而是 FFGO 接入前的 I2V 蒸馏基线验证。**
   这一步的价值在于确认 FastGen 的 `Wan2.2 I2V` 蒸馏主干可运行，为后续接 `FFGO A14B + LoRA` teacher 提供基线。

3. **显存是当前最大的实验边界。**
   即使使用 2-GPU FSDP 和 CPU offload，单卡峰值显存仍接近 30GB；原生 CFG teacher pass 会额外触发约 `1.27 GiB` 级别分配，导致 OOM。

4. **4-GPU 并不是自动解决方案。**
   本周测试过 4-GPU 路线，仍然在类似位置 OOM。因此问题不只是 GPU 数量，而是 DMD2 多网络组合、CFG teacher pass 和当前 FSDP/offload 方式共同造成的显存峰值。

5. **当前已经拿到可继续推进的正式 run。**
   `1000 iter` checkpoint 已保存，`5000 iter` 续训已从 `0001000` 成功恢复，并在 `1100 iter` 打印正常 loss，说明 checkpoint resume 和长训流程可用。

6. **后续接真实 FFGO teacher 不能直接替换路径。**
   如果 FFGO 仍保持公开的 `Wan2.2-I2V-A14B + LoRA` 形态，需要额外解决 LoRA 加载、A14B/5B 架构差异、I2V 条件输入和显存策略问题。
