# 调研任务书模板 + 验收 Checklist

来源：rdbp_face 项目 R1–R4 任务书的通用化提炼。A 节是给内容 agent 的启动 prompt 模板（`<>` 处填写）；B 节是规划 agent 的验收清单。

## A. 任务书模板

```markdown
你是一个强力 research agent，本次任务是 **T<N> 文献调研：<主题>**。这是纯调研任务，不是工程任务。

工作目录：

<项目绝对路径>

## 角色与边界（先读这一节）

- 本目录的 CLAUDE.md 是为工程 agent 写的，本次会话**忽略其中的角色设定和上下文加载规则**。
- 不要读代码目录，不要 ssh 任何远端机器，不要跑训练/评估，不要修改 research/ 以外的任何文件。
- 本地**只读 <2–3 个指定文件>**，其余背景本 prompt 已给足，不要再读别的。
- 调研用可靠来源：论文原文、arXiv、OpenReview、CVF、官方代码库。**近两年的工作必须实时检索，不要凭记忆**（覆盖 <本领域主要会议> 2024–2026 与 arXiv 近两年）。
- 可并行的检索尽量并行。控制聚焦：清单表 10–20 篇、精读 3–5 篇，不做百科式综述。

## 项目背景（一段话）

<项目目标 + 本调研服务的里程碑（汇报/投稿及其日期）>

## 我们的方法（文献对比用的准确描述）

<论文语言，来自 T0：结构（什么冻结/可训/从哪分叉）、信号（什么信息/在线离线/可解释性）、
约束或目标（数学形式、作用对象、方向）。不要出现数据格式、脚本名等工程名词。>

## 实验现状（结论可直接引用，不必读实验报告）

<已证明（带数字）/ 未证明 / 进行中；诚实呈现负结果。>

## 已确认锚点（前序任务注入；首个任务可无此节）

<前序调研确认的必比先例、带日期的更正、可复用的检索词组合、"不要重复调研"的范围声明。>

## T<N> 要回答的问题

<3–6 个，从谱系盘点到具体裁决；最后一问通常是：
"如果要讲投稿故事，本调研能支持哪些主张？逐条判：文献支持 / 部分支持 / 不支持。">

## 产出

写入文件：`research/T<N>_<slug>.md`（覆盖写，文件名固定）

结构：
1. **Executive Summary**：5–8 条，直接说结论。
2. **论文清单表**：Paper / Year / Venue / Problem / Method Type / <任务相关列> / Relation to our project / Useful or Risk。
3. **3–5 篇精读卡**：核心问题、方法机制、关键公式或思想、实验设置与证据、对我们的启发、我们如何区别于它（含"不能 claim 的部分"）。
4. **Gap 分析**：逐主张裁决；对"没有先例"类结论，**必须附上检索过的关键词组合与覆盖范围**，不许直接断言空白。
5. **对 <里程碑> 的可用表达**：3–5 条可直接使用的 bullet。
6. **对后续实验 / 写作的具体建议**。

格式要求：每篇论文给 arXiv/DOI/OpenReview 链接；不确定的事实标注"待核实"；每节结论先行；中文撰写，论文名与术语保留英文。

## 调研纪律

- 每篇论文都要说清与本项目的关系，不只列标题。
- **不夸大 novelty**：严格区分"已有工作已做过 / 类似但不完全一样 / 可能存在空白"三档。
- 不在本领域但机制相关的工作放补充部分并说明区别。
- 产出服务 <里程碑> 与投稿规划，不是百科综述；语气专业、清楚、克制。
- 完成后在对话里给 ≤10 行执行总结：<该任务最关心的 2–3 个交付点，如"gap 是否成立 / 对 X 最有用的 3 条"。>
```

## B. 验收 Checklist（规划 agent 对每份报告必做）

1. **结构合规**：六段式齐全；每节结论先行；体量克制（±200 行量级）。
2. **覆盖检查**：链接数 ≈ 论文数；"待核实"有标注；每条"无先例"裁决都附了检索词组合。
3. **引用抽查**：自己知识能核实的逐条核对（机制描述、消融数字、venue）；核实不了的新条目（近一年）确认已标"待核实"；**载重条目**（支撑关键判词的那几篇）列入"引用前必点原文"清单并告知用户。
4. **一致性**：与前序报告有矛盾或更正时，要求内容 agent（或亲自）在被更正的报告里写**带日期的回填更正注记**，不悄悄改正文。
5. **纪律**：novelty 三分法执行到位；无绝对化断言（"首个/首创"必须有检索覆盖支撑且加"据我们所知"）。
6. **整合动作**（验收通过后立即做，一步不省）：
   - research/README.md 加状态行（✅ 日期 + 关键裁决一句话）；
   - 锚点与更正注入后续任务书；
   - 报告的"实验建议"逐条裁决采纳/不采纳，采纳项写进项目实验计划并注明来源任务号；
   - 全部任务完成后更新 `summary_for_<里程碑>.md` 汇总页（格式见 workflow.md Phase 2）。
